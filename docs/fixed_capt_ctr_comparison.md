# 固定CAPTとCTR最適LDPの比較

`fixed-capt-ctr-comparison` は、保存済みの文脈別CAPT証明書を読み込み、その公開プロファイルと文脈1組を評価する。事前に対象の証明書、文脈、格子、平滑化候補、クリップ幅、信頼水準、シフト仮定を決める。証明書とモデルのディレクトリ構造は元のランから引き継ぐ。

```bash
uv run capt12 fixed-capt-ctr-comparison \
  --certificate /path/to/mechanism-run/certificate-DESIGN-context-00.json \
  --settings configs/fixed_capt_ctr_comparison.yaml \
  --output outputs/fixed_capt_ctr/context-00.json
```

Parquetの配置が証明書作成時と違う場合は `--data-root` に同じスナップショットの配置先を指定する。設定例では時系列ホールドアウトの経験損失を出す。母集団の信頼限界は、下記の標本仮定が妥当な対象に対して `iid_utility_target: true` を設定した場合に出す。複数の文脈や証明書を同時に主張する場合は、対象を事前に決め、全対象に誤認証確率を配分する。

## 属性予算

- `beta_R` は、証明書が再構成したブロック信頼集合と順序付き辺から、固定CAPTの最悪の尤度比を再計算して上方丸めした共通スカラー。入力行は保存された重みをカテゴリ確率として解釈する。元トークン集合からブロックへの像がブロック信頼集合の部分集合なら、この値は両機構に課す共通の許容上限になる。
- `raw_shift_tv: null` は、ブロック信頼集合の元トークン側逆像を不確実性集合とする。較正に使える元トークン側のシフト仮定がないので、TVとホッケースティック発散に一律上界1を使う。有効な比較予算は通常 `beta_R` になる。ブロックTVから元トークンTVを推定する処理はない。
- `raw_shift_tv` を設定すると、`D_cert` のラベルを取得せずに元トークンを再集計する。凍結エンコーダとブロック写像で既存の認証カウントを再現できることを確認する。保護群ごとに全事象へのHoeffdingと群間の和集合評価で作ったTV半径に、指定した元トークンシフト上限を加える。未観測群の球は単体全体になる。実際の不確実性集合は、これらのTV球とブロック信頼集合の逆像の共通部分。元トークンシフト上限は外部仮定であり、ブロックのシフト幅からは導けない。
- 較正器は、既知の一点分布なら線形走査、低次元のTV球なら全事象の列挙で一律較正式を評価する。大きい入力のTV球や、ブロック逆像との共通部分に制約が残る場合は保証付き上界として記録する。全事象列挙の設定上限は16。全ての有限予算が保証を満たす場合は、比較の損失に `lambda = "infinity"` として恒等チャネルの極限値を使う。
- `equal_epsilon` は保存済みの設計予算と同じ名目LDP予算。共通の属性予算までこのクラス全体に保証できる場合は、`common_attribute_beta_uniformly_guaranteed` に記録する。従来の結果キー `optimal_ldp` は固定コストのブロックLDPとして引き続き使う。

## 母集団と分割

| 分割 | 用途 |
| --- | --- |
| `D_model`、`D_design` | 保存済みエンコーダ、参照予測器、写像・チャネルの設計 |
| `D_cert` | 属性プライバシー認証と、元トークン較正を有効にした場合の群別カウント |
| `D_predict_train` | 出力確率を重みにしたCAPT・LDPのCTR推定と、LDPチャネルの設計 |
| `D_predict_validation` | 平滑化の選択、経験同時分布におけるBayes値と母集団の効用信頼限界の計算 |
| `D_test` | チャネル、CTR、較正予算、ハイパーパラメータを固定した後の最終評価 |

例では既存の監査用 `D_attack_train` を日付で2分する。既存監査は従来どおり別の分析として実行できる。同じ日の訓練・検証への重複を禁止し、読み込んだデータ内で表示IDの重複も確認する。分析対象は表示ログに指定プロファイルを適用した、固定公開文脈内のユーザー日母集団。Criteoには観測されたプロファイル選択がないため、実際にそのプロファイルを選ぶ利用者のCTRは識別できない。

認証と新しい効用評価は、まず安定ハッシュでユーザー日ごとに1表示を選び、次に公開文脈で絞る。既存の全表示での固定参照評価は従来の分割・抽出を使い、新しいJSONの固定参照損失は再学習の結果と同じユーザー日集合で計算する。オンラインmemoizationは各エポック・プロファイル・公開文脈の先頭リリースを以降も再利用する。この評価は選択した表示への単発リリースの期待損失を測る。繰り返し表示や最初のトークンの時系列への依存は別の評価対象になる。

母集団の効用認証には、検証・テストの選択済みユーザー日が、各標本内で条件付き独立同分布であり、同じ対象 `P(Y,Z | S=s,B=b)` に従うという仮定を使う。日付の分離やユーザー日への制限からその仮定は証明できない。属性の認証にも、証明書の標本条件と、対象での分布が指定したシフトの範囲に入るという前提がある。

## 損失と判定

- SPRは元トークンをCTR順に並べ、全ての連続分割数の最適コストを1回の動的計画法で計算する。時間は入力サイズの3乗、メモリは2乗に比例する。CTRの大きな入力では、格子点にアップグレードした比較分布のSPR下界と、区間に集約した分布のSPR上界を出す。区間側から設計した実行可能なLDPチャネルを再学習評価する。CAPTのブロック写像はLDPの設計に使わない。
- 格子とSPRの境界は、整数カウントからの有理数計算と方向付き丸めを用いる。`validation_plugin_v_z` は検証標本の経験分布についての値。階段列LPは小規模問題での独立照合に用いる。
- 再学習済みのテストlog lossは出力分布で平均した損失であり、対応する母集団Bayes損失は別の量。`population_v_z_bounds` は、検証分布のTV信頼半径による連続性補正、二点格子の下限、固定したLDP候補のテスト上限を使う。
- `certified_win` はCAPTのテスト損失上側信頼限界が最適LDPの母集団下側信頼限界より小さい場合。 `certified_loss` はCAPTの母集団Bayes下側信頼限界が最適LDPの上側信頼限界より大きい場合。残りは `inconclusive` となる。母集団の効用仮定を有効にしない実行では `assumptions_not_enabled` を出す。損失差は LDP最適損失からCAPTのBayes損失を引いた符号で出力する。

K=4096では新しいLDP計算がK×Kの行列を作らず、格子点数でSPRの計算量が決まる。保存済み証明書の検証では既存のトークンチャネル展開を行うため、メモリ使用量は別途見込む。Kに依存する経験同時分布の信頼半径は、希少文脈では大きくなりやすい。二点下限はKに依存せず、CTRの差を粗く評価する。元トークン較正も未観測群や大きいシフト幅で等 `beta_R` に近づく場合がある。

## 合成パイロット

```bash
uv run pytest -q tests/unit/test_optimal_token_ldp.py
uv run pytest -q -s tests/integration/test_fixed_capt_ctr_comparison.py
```

乱数seedは12064。K=64、CAPTは2ブロック、保護群は2つで両方向。認証6,000件、訓練・検証・テスト各5,000件を別々に生成した。以下の損失は自然対数の単位。K=64の証明書検証からJSON生成まで約1.9秒。K=4096は格子計算単体を検証した。

認証済み `beta_R` は0.408362。TV上界は0.781370、ホッケースティック発散の保守的上界は0.728563。CAPTの再学習テスト損失は0.526055、固定参照テスト損失は0.547597、テスト損失上側信頼限界は0.638532。既知の合成分布でのCAPT Bayes損失は0.531595。

## 固定CAPTの理論診断

保存済みの比較JSONと認証済みチャネルから、同じ抽出方法で検証データの
元トークンとクリックの同時度数を再現する。全体の損失は各文脈の検証件数で
加重し、文脈ごとにLDPのチャネル・予測器を最適化する。訓練日とテスト日は
件数の照合に使い、クリックラベルは検証日から取得する。

```bash
uv run capt12 fixed-capt-theory \
  --results outputs/fixed_capt_ctr \
  --certificate-dir /path/to/mechanism-run \
  --data-root data/CriteoPrivateAd_release/data \
  --output outputs/fixed_capt_theory
```

証明書の保存場所が比較JSONに記録されたパスと同じ場合は、`--certificate-dir`
を省略できる。移動した場合は同じファイル名とハッシュの証明書を含む
ディレクトリを指定する。各文脈の証明書、実際の公開文脈値、検証件数を照合し、
検証0件の文脈を集約から除く。結果は新規ディレクトリの `contexts.csv`、
`theory.json`、`report.md` に出力する。

予算1での判定は、CAPTの認証予算と、方向付き丸めを含む経験Bayes損失の
境界を使う。交差点は独立した下側・上側の判定を二分探索する。
`--cross-initial`、`--cross-cap`、`--cross-tolerance` で探索範囲と刻みを指定できる。
`epsilon_cross_upper: null` は探索で有限上界を得られなかったことを表す。
`epsilon_cross_status: infinite` は検証分布上で有限の交差点が存在しないことを表す。
`empirical_win_interval_empty: null` は空かどうか未確定。
格子は既存比較の設定を使用し、`--grid-subdivisions 4` などで細分化できる。

母集団の勝敗欄は経験分布の判定とは独立している。予算1の既存の統計的区間があれば
文脈別に引き継ぐ。複数文脈を同時に覆う全体の母集団区間は別途構成が必要になる。
